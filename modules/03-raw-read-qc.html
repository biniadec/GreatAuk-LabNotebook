Module 03 of 10

Raw Read QC

This module answers one question: what do the raw Great Auk reads actually look like, before we change anything? It is diagnostic, not corrective. You will run FastQC and MultiQC, open and read their real HTML reports, and write a QC diagnosis — but you will not trim, filter, merge, map, or otherwise modify a single FASTQ file. That's Module 04.

Learning objectives

  • Tell FASTA and FASTQ apart confidently, by structure, not just by filename
  • Explain what a Phred quality score means, without the maths overwhelming the concept
  • Explain what FastQC does — and does not do — to a FASTQ file
  • Run FastQC on a real Great Auk run, interactively, and read its HTML report
  • Interpret the major FastQC panels biologically, not as a pass/fail scoreboard
  • Distinguish FastQC's surface patterns from confirmed ancient-DNA damage
  • Run FastQC and MultiQC across all 13 libraries reproducibly
  • Compare libraries and write a QC diagnosis that justifies later preprocessing choices

01

FASTA vs FASTQ

✓ Complete
Concept

FASTA and FASTQ are file formats, not analysis methods — worth saying plainly, since the names and the letters FASTA/FASTQ are easy to blur.

FASTAFASTQ
StoresSequence onlySequence + per-base quality
Record lengthHeader + sequence (any number of lines)Exactly 4 lines per read
Typically representsA reference genome, assembly, contig, scaffold, chromosome, or consensus sequenceOne sequencing read
Common extensions.fa, .fasta, .fna.fastq, .fq (usually .gz)
In this projectThe razorbill reference genomeThe Great Auk raw reads

A FASTA record can represent something enormous — an entire chromosome. A FASTQ record is almost always small — one read, a few dozen to a few hundred bases.

>scaffold_12
ACTGACTGACTGGGTTCAGCTAGCATCGATCGTAGCTAGCATCGATCG...
1 · ID@read_001
2 · SequenceACTGACTG
3 · Separator+
4 · QualityIIIHHHGF

02

What does read quality mean?

✓ Complete
Concept

Each base call gets a Phred quality score — higher means a lower estimated probability that base is wrong. It's per-base, which is exactly what FASTQ's quality line (line 4) encodes, one character per base of line 2.

Phred scoreApprox. error probabilityApprox. accuracy
Q101 in 1090%
Q201 in 10099%
Q301 in 1,00099.9%

Sequencing quality is not the same thing as biological usefulness. A low-quality base might still be biologically real; a high-quality base can still come from contamination or an artifact. Phred scores tell you about measurement confidence, not biological importance.

Task

Look at the quality line from Exercise 1 (IIIHHHGF). Without calculating anything precisely, which end of the read looks higher quality, and which looks lower? (Hint: later letters in this range are generally higher quality than earlier ones in standard Phred+33 encoding.)

Check yourself

Why isn't a low Phred score automatically a biological problem, as opposed to a measurement one?

03

What does FastQC actually do?

✓ Complete
Concept

FastQC is a diagnostic tool: it reads a FASTQ file, summarizes its properties, and reports them — it never modifies the file itself.

One FASTQ file
↓
FastQC reads and summarizes it (never modifies it)
↓
An HTML report + a .zip of the same data, with a pass/warn/fail flag per module
↓
Your biological interpretation

You'll meet these modules properly in Exercise 6 — no need to memorize them now: Basic Statistics, Per base sequence quality, Per sequence quality scores, Per base sequence content, Per sequence GC content, Sequence Length Distribution, Sequence Duplication Levels, Overrepresented sequences, Adapter Content.

A FastQC flag ≠ automatic failure. FastQC's pass/warn/fail thresholds were calibrated against typical modern sequencing libraries. Historical and ancient DNA can validly trigger warnings or failures that don't mean the data is unusable — you'll see this directly in Exercises 6–7.
Task

Before running anything, predict: which one or two of the modules listed above do you expect might show a warning for ~170-year-old museum DNA, and why? (You'll check this prediction in Exercise 7.)

Check yourself

Does FastQC ever conclude that an entire dataset is unusable, or does it only ever flag individual modules?

04

Run FastQC on one real library

✓ Complete
Concept

For a single quick exploratory run like this one, an interactive Slurm job is more convenient than writing a whole batch script for one command — it gives you a live shell directly on a compute node. Mjolnir's documentation gives this verified pattern for starting one: 

srun --partition=cpuqueue --qos=normal --nodes=1 --cpus-per-task=2 --mem-per-cpu=2G --time=01:00:00 --pty bash

The specific resource numbers (2 CPUs, 2 GB per CPU, 1 hour) are a modest teaching allocation chosen for this exercise — Mjolnir's docs don't prescribe particular values for FastQC specifically, just this general pattern for requesting an interactive session.

Task

Start an interactive session, check whether fastqc is available, load it, create an output directory, and run FastQC on SRR32500061 — the smallest run, already on disk from Module 02.

Hint

FastQC's -o output directory must already exist — it won't create one for you.

Show command
# request an interactive session srun --partition=cpuqueue --qos=normal --nodes=1 --cpus-per-task=2 --mem-per-cpu=2G --time=01:00:00 --pty bash # once you have a shell on a compute node module avail fastqc module load fastqc/<version> mkdir -p analysis/raw_qc/fastqc fastqc -o analysis/raw_qc/fastqc raw_reads/great_auk/SRR32500061/SRR32500061.fastq.gz # leave the interactive session when done exit

Replace <version> with whatever module avail fastqc actually shows you.

05

Open and inspect the FastQC HTML report

✓ Complete
Concept

FastQC produced two things: SRR32500061_fastqc.html (a fully self-contained report — every plot is embedded directly in the HTML, so this one file is all you need to view it) and SRR32500061_fastqc.zip (the same data in parsed form, which should stay on Mjolnir — Exercise 9's MultiQC step reads directly from files like this one).

Mjolnir is remote, so you can't just double-click the HTML file where it sits — you need to copy it onto your own computer first. scp ("secure copy") does exactly this, over the same SSH connection you already use to log in.

The command has the shape scp <username>@<mjolnir-host>:/full/path/to/file .:

  • <username>@<mjolnir-host>: — the remote server (your KU-ID and the same host you SSH into)
  • /full/path/to/file — where the file lives on Mjolnir
  • . — "here" — the current directory on your own computer

This only matters for small result files like HTML reports — never copy the large raw FASTQ files back to your laptop this way.

Task

Run scp to copy SRR32500061_fastqc.html from Mjolnir to your own computer, then open it in a browser.

Hint

Run this command from your own computer's terminal, not from inside your Mjolnir SSH session — scp needs to start from the machine you want the file to end up on.

Show command
# run from your own computer's terminal — not on Mjolnir scp <KU-ID>@mjolnirgate.unicph.domain:/full/path/to/analysis/raw_qc/fastqc/SRR32500061_fastqc.html .

Replace /full/path/to/... with the real absolute path pwd gives you on Mjolnir. Once it's downloaded, open the file directly — double-click it, or drag it into a browser window.

06

Interpret the FastQC plots

✓ Complete
Concept

For each panel in your real report, ask the same four questions: what does it measure? What pattern do you actually see? Is that pattern necessarily a problem? Would you act on it immediately, or investigate further?

PanelWhat it measuresHow to interpret it in historical DNA
Basic StatisticsTotal sequences, sequence length, GC%Raw read length reflects the sequencing setup, not necessarily the original DNA-fragment length. A ~101-bp read can come from a shorter molecule if sequencing continues into adapter sequence.
Per base sequence qualityBox plots of quality by position along the readQuality often declines toward the end of Illumina reads, but this is not specific to historical DNA. Interpret the profile before deciding whether any bases need trimming.
Per sequence quality scoresDistribution of each read's average qualityA lower-quality subset may indicate technical variation among reads; it is not by itself an ancient-DNA signature.
Per base sequence contentA/C/G/T proportions by positionEnd-position biases can reflect fragmentation and library-preparation effects. FastQC alone cannot tell whether a pattern represents ancient-DNA damage.
Per sequence GC contentDistribution of per-read GC%Shifts, broadening, or extra peaks can have several causes, including mixed sequence sources or technical bias; FastQC alone cannot identify the cause.
Sequence Length DistributionSpread of read lengthsIn these raw reads, lengths may be nearly uniform because sequencing was performed to a fixed read length. This does not mean the original DNA molecules were equally long. Length distributions become especially informative after adapter trimming.
Sequence Duplication LevelsHow often identical reads recurHigh sequence duplication can be consistent with low library complexity and substantial amplification of low-input historical DNA. FastQC sequence duplication is not the same as identifying PCR duplicates after mapping.
Overrepresented sequencesSpecific sequences appearing unusually oftenAdapter sequence is one possible cause, but other recurrent sequences can also be overrepresented; inspect what FastQC identifies rather than assuming.
Adapter ContentDetected adapter sequence by positionShort DNA inserts can cause sequencing to continue into the adapter. This is particularly relevant for fragmented historical DNA and is a key observation for deciding on adapter trimming.
Read length ≠ molecule/insert length. This distinction matters for these ~101-bp Great Auk reads: a short historical-DNA insert can still yield a full-length sequencing read through adapter read-through.
Don't treat FastQC's red/orange/green icons as a verdict. Read the plot, not just the icon.

07

What can ancient DNA make look "weird"?

✓ Complete
Concept

Several real, well-documented features of historical/ancient DNA can make FastQC plots look unusual: short fragments; adapter read-through (when the DNA fragment is shorter than the sequencing read, the read runs past the fragment into adapter sequence); unusual base composition near read ends; high duplication from limited library complexity; and damage-associated substitutions concentrated near molecule termini.

FastQC does not diagnose authentic ancient-DNA damage. It can show you a surface pattern — for example, unusual base composition near read ends — that is consistent with damage. It cannot confirm genuine deamination. That requires dedicated tools (e.g. mapDamage) applied to mapped reads, which comes later in this project.

Keep these three separate: what FastQC can actually show you (a pattern); what you can only hypothesize from it (a possible cause); and what requires real downstream testing (confirmation).

Task

Revisit your Exercise 3 predictions. Which modules actually showed a warning or fail? Which of your predictions were right, and which weren't?

Check yourself

If your report shows an unusual base-composition pattern near the read ends, is that proof of ancient DNA damage? What would you actually need to do to test that hypothesis properly?

08

Run FastQC on all 13 Great Auk libraries

✓ Complete
Concept

Now that you understand one report, scale up — the same way Module 00 taught you to move from an interactive exploration to a reproducible batch job. FastQC can take many input files at once and process them in parallel with -t, which is simpler and more honest than writing a 13-iteration shell loop.

Task

Write and submit a batch script that runs FastQC on all 13 Great Auk FASTQ files in one call, writing everything into the same analysis/raw_qc/fastqc/ directory.

Hint

FastQC's own filename-based naming (e.g. SRR32500061_fastqc.html) already keeps the 13 outputs distinguishable in one flat directory — no need for per-run subfolders.

Show command
cat > fastqc_all.sbatch <<'EOF' #!/bin/bash #SBATCH --job-name=fastqc_all #SBATCH --partition=cpuqueue #SBATCH --qos=normal #SBATCH --nodes=1 #SBATCH --cpus-per-task=8 #SBATCH --mem-per-cpu=500M #SBATCH --time=01:00:00 #SBATCH --output=analysis/raw_qc/fastqc_all-%j.out #SBATCH --error=analysis/raw_qc/fastqc_all-%j.err module purge module load fastqc/<version> mkdir -p analysis/raw_qc/fastqc fastqc -t 8 -o analysis/raw_qc/fastqc raw_reads/great_auk/*/*.fastq.gz EOF sbatch fastqc_all.sbatch

-t 8 processes up to 8 files simultaneously — all 13 will still complete in one job, just with a short queue of 5 once the first 8 are underway.

Check yourself

Why does one fastqc call with -t 8 handling all 13 files make more sense here than either 13 separate commands or 13 separate job submissions?

09

Summarise all libraries with MultiQC

✓ Complete
Concept

FastQC analyzes one FASTQ at a time. MultiQC collates many FastQC outputs — reading the .zip files, not the HTML — into a single comparative report.

13 individual FastQC outputs (.zip files)
↓
MultiQC scans and aggregates them
↓
One comparative HTML report, all 13 libraries side by side

MultiQC itself is lightweight, but since you'll already be inside a real analysis job from Exercise 8, it makes sense to add it as a second command in the same batch script rather than hopping back to the login node for one more step of the same workflow.

Task

Check that multiqc is available, then add it to your Exercise 8 script (or a short follow-up job) to summarise analysis/raw_qc/fastqc/ into analysis/raw_qc/multiqc/. scp the resulting report down and open it, the same way you did in Exercise 5.

Show command
module load multiqc/<version> mkdir -p analysis/raw_qc/multiqc multiqc analysis/raw_qc/fastqc -o analysis/raw_qc/multiqc

Produces multiqc_report.html — also self-contained, same scp approach as Exercise 5.
